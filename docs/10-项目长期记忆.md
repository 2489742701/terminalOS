## 2. 板级硬事实（改错开不了机）

- **Flash 模式 = DIO**（QIO → bootloader 卡死 → TG0WDT 每秒复位），直烧也须 `--flash_mode dio`。
- **PSRAM = OPI**（`arduino.memory_type = qio_opi`）。**DIO 与 OPI 必须同时成立**。
- ⛔ **禁 `flash_size=16MB` / `partitions_16MB.csv`** → 分区越界 → `while(1)` → `rst:0x3` 无限重启**且无 panic**。
- 成功标志：`[BOOT] Geek Terminal ready` + `buf ... ptr=0x3d8712dc`（`0x3d…` = PSRAM）。
- 无害告警：`gpio_set_level(227)` / `Invalid pin selected` = GT911 操作 INT/RST = -1。

## 3. 显示

- **PCLK = 10MHz**（降频抗花屏，勿改回 16）；LVGL 缓冲 PSRAM 双缓冲 × 120 行。
- ST7701S：`st7701_type1_init_operations` + RGB 时序 H 10/8/50、V 10/8/20、IPS/BGR=true。都别动。
- IDF 4.4 不可行（别浪费时间）。**分水岭**：静态正常只刷新时乱 → 带宽争抢；静态也花 → 时序错。

## 4. 内存

- ⚠️ **`CONFIG_SPIRAM_MALLOC_ALWAYSINTERNAL=4096`：≤4KB 的 malloc 一律进内部 DRAM。**
  布局树节点 / text_content / href·class·style 拷贝**全都是小分配** → 解析一页 DRAM 掉 40KB，
  PSRAM 7.29MB 纹丝不动。这是"加载第二页崩"的真正隐患。
- **已修**：`tb_alloc` / `tb_calloc`（`heap_caps_malloc(MALLOC_CAP_SPIRAM|8BIT)`，malloc 兜底），
  用于 `safe_strdup` / `safe_strndup` / `layout_node_create` / dom_renderer 的 text_content。
  **解析开销 40KB → 4KB**（实测 DRAM 谷值 205KB → 246KB）。
  ⚠️ ESP-IDF 里 `free()` == `heap_caps_free()`，调用方**不用改** free。
- 判据：PSRAM free 恒定 = 大块预分配；DRAM 逐页下滑 = 有小分配漏走 DRAM。
- 无 MMU：不 `lv_obj_del()` 永不释放。LVGL 池已在 PSRAM（开机 DRAM free 250KB，PSRAM 7.2MB）。
- 量化用 `heap_caps_get_free_size(MALLOC_CAP_INTERNAL)`；🚫 `xPortGetFreeHeapSize()` 含 PSRAM。
- 🚫 运行时禁 `heap_caps_get_largest_free_block()` / `get_info()`（持堆锁撞 WiFi → wdt）。
- 任务栈只从内部 DRAM 分配 → 后台任务一次性常驻复用（notify 唤醒），勿反复 create/delete。
  fetch 任务栈 16384（实测峰值 3712 B）。
- HTTPS 上限 786432 B；chunked 读取**必须钳 `room`/`want`**（写穿堆表现为
  WiFi 驱动 `block_trim_free heap_tlsf.c:371`，看着像 WiFi 的锅）。

## 5. 内存账本（为什么 PSRAM 空着、DRAM 见底）

- DCache 仅 32KB / line 32B；PSRAM OPI 80MHz，与片内 flash 同一条总线分时复用。
- 显示 RGB 并行 + GDMA：帧缓冲在 PSRAM，靠 bounce buffer（须内部 DMA 内存）中转
  —— 这才是 PCLK 只能 10MHz 的根因。
- 别想"运行时搬来搬去"：无 MMU，两段物理地址，搬运 = 手写 GC。

## 6. 浏览器：平铺 + 搜索优先（路线 D）

> 路线 A（还原 CSS 版面）已放弃，路线 C（转码代理）不做。详见 `12` / `13`。

- **平铺**：`layout_set_flat_mode(true)`（默认开，串口 `flat on|off`）。不建容器、满宽居左。
  根因：CSS 算出的 x/y/height 大量为 0，`create_label` 的 `(void)x;(void)y` 根本不消费坐标，
  唯一吃坐标的 `create_container` 就成了压盖/零高的源头 —— 不建容器则症状全消。
- **行合并**：无文字壳子透明钻入 + **跨壳（父不同）只放行链接**，普通文本不放行。
  `<li><a>` 靠 `li_is_link_wrapper()` 保留内层 `<a>`。
- **胶囊 chip**：链接/小按钮画成带框圆角块，排进 `LV_FLEX_FLOW_ROW_WRAP`。`create_row_wrap` 不收 x/y。
- ⚠️ **结果条目里的 `<a>` 根本不在布局树里**：`<li class="b_algo">` 有文本 → 被判纯文本叶子、
  不递归 → 标题链接丢失 → 整条点不动。靠 `subtree_first_href()` 把子树第一个 `<a href>`
  的**绝对地址**记到 `li->href_resolved`。**只对 li 做，不做 div**（div 整块可点 = 误触）。
- **搜索结果按块渲染**（`dom_renderer.cpp::li_has_block_children()`）：`<li>` 有 **≥2 个块级子元素**
  （跳过 link/script/style/meta/br/hr）就**不抽文本**，递归让各块各自成行。
  必应 `b_algo` = 来源行 / `<a><h2>`标题 / `<p>`摘要 三块。副作用正是想要的：标题 `<a>` 活下来 → 可点胶囊。
  ⚠️ **补充**：`nav/ul/ol/table` 这类结构性容器**出现一个就判块级** ——
  分页 `<li class="b_pag">` 只有一个 `<nav>`，够不到"≥2"门槛会被压成一行。
- ✅ **链接可点**（`register_link_handler`）。三个坑：
  ① 🚫 别在 CLICKED 回调里 `startFetch()` → 走 `g_linkPending` 延迟通道，下一 tick 才导航；
  ② 必须用**绝对 URL**（`href_path` 是纯路径）→ `flat_link_target()` 优先 `href_resolved`；
  ③ URL 必须 `strdup`（布局树渲染完就 free）→ 靠 `LV_EVENT_DELETE` 回收。诊断看 `clickable links=M`。
- ✅ **自建搜索首页**（`showSearchHome()`）：搜索框 + 必应/百度切换 + 常用词胶囊 + 新闻源占位。
  键盘常驻隐藏挂在屏上。首次进浏览器不再自动抓门户页。
  ⚠️ `lv_keyboard` 只有 ASCII，无拼音 IME → 中文搜不了，只能靠预设胶囊。
- ⚠️ **必应的搜索框是 `<textarea id="sb_form_q" type="search" rows="1">`，不是 `<input>`。**
  当年为省 DRAM 把 `ELEMENT_TEXTAREA` 整支跳过，导致必应里**看不到搜索框**；
  那条限制在 LVGL 池搬 PSRAM 后早已不成立。现在 input **和 textarea 都渲染成单行输入框**。
  ⚠️ textarea 的 `form_value` 是整段 innerText（可能几十 KB）→ 截到 256 B 再塞。
  诊断：`[Browser] input: ph="..." val="..." 440x40`。没这行 = 又被 DOM 裁剪吃掉了。
- ✅ **SERP 壳子过滤** `flat_is_serp_chrome_link()`：丢 `filters=ex1`（时间筛选）/ `qpvt=`
  / `FORM=HDRSC`（顶部导航）/ 垂搜路径 / `first=` 且**文本是 1~3 位纯数字**（页码）；
  `FORM=PORE`（下一页）**反向保留**。
  ⚠️ `first=` **不能无条件删**：`<li>` 会从子树继承 href，分页容器会被连坐掉，「下一页」跟着消失（踩过）。
- ✅ **诊断**：串口 `flatdump <n>` 调 dump 行上限（默认 60）。分页排在第 60 行之后，
  看不到会误判成"没渲染"。
- ✅ 平铺跳过外部 CSS：cn.bing.com 原本要串行拉 30+ 个 CSS = 30 次 TLS ≈ 1 分钟。

## 7. 浏览器：页面缓存 + 下载 + 内置服务

- **缓存**：URI→HTML 存 PSRAM（3 格 / 单页 400KB / **TTL 5 分钟**，满了挤最老的）。
  命中走 `tactilebrowser_parse_html_buffer()`（跳过下载，两阶段，不碰 LVGL）。
  下载器包装 `cache_download_html()` 顺手存一份（引擎会 free 原 buffer，**必须拷**）。
- **下载**：底栏「下载」键 + 串口 `dl` → 写 LittleFS `/p<hash>.html`。
  ⚠️ 首次 `LittleFS.begin(false)` 会失败，必须 `begin(true)` 格式化；分区约 1.5MB。
- **看已存页面**：`serve` → PC 浏览器访问 `http://<板子IP>/`（实测 192.168.50.147）。
- ⚠️ **修过的 bug**：`ls` 曾无条件 `LittleFS.end()`，会把正在跑的服务器搞成 404。
  现在服务器在跑时不再卸载。
- 渲染完 HTML 原文由引擎内部 free，只留 URI + 缓存拷贝。

  直接 `lv_obj_get_scroll_bottom()` 恒为负（曾一直 total=80），看着像"内容被压扁"。
- **bootloop 先看 `Saved PC`**：`rst:0x3` + 无 panic + PC 恒定 = 主动死循环。
- **二分法**：极简工程 `tools/minimal_test/`；它也挂 ⇒ 配置问题。
- CH340 卡死（Error 31 / ports:0）：先软件复位（Disable/Enable-PnpDevice），真掉线才拔线。
  **判据用 `Get-PnpDevice -PresentOnly`**：查得到 = 软件卡死可救；查不到 VID_1A86 = 物理掉线。

## 12. 库级坑

- **随包 LVGL `lv_draw_sw_arc.c` 有 bug**：部分圆弧分支无条件 `free` 未初始化的 `mask_in_param`
  → LoadProhibited 开机必崩。已补守卫；`icons.cpp::drawWifi()` 改用折线不碰 `lv_draw_arc`。
- `font_zh_16` 曾缺全部 ASCII → 数字/英文全豆腐块。**符号表必须同时覆盖 CJK 和 ASCII。**

  → `lib_ignore = Time`；time API 用 `-D_GNU_SOURCE`。
- safe-delete 按"单进程内累计删除数"计 50/轮 → 日志停在 "Took 17.81 seconds" + [FAILED]。
  `build_run.py` / `flash_run.py` 已设阈值 100000。
