## 1. 它是什么

ESP32-S3 上的一台**口袋终端**：480×480 圆屏，息屏/锁屏，Launcher + 时钟 + 设置 + 天气 +
WiFi + 浏览器等多屏，核心卖点是**自带一个能跑的网页浏览器**（抓 HTML → 解析 → 排版 →
LVGL 渲染 → 可点链接）。

| 项 | 值 |
|---|---|
| MCU | ESP32-S3（16MB Flash / 8MB **OPI** PSRAM） |
| 屏 | 4.0" 480×480 ST7701S，**RGB 并行** |
| 触摸 | GT911（I²C） |
| 平台 | PlatformIO + Arduino core 2.x（IDF 4.4） |
| UI | LVGL 8.3.0-dev（vendored，改过源码） |
| 解析 | Lexbor（vendored 在 `src/browser_engine/lexbor/`） |
| 串口 | COM7 @ 115200 |

⚠️ **动任何显示 / 构建配置之前，先读 [`01` 的「板级硬事实」](01-板级硬事实与构建烧录.md)** ——
那几条改错直接开不了机。⚠️ **动浏览器排版 / 搜索之前，先扫一遍 [`09` 坑点速查表](09-坑点速查表.md)**。

## 2. 五分钟跑起来

### 2.1 构建

```bash
cd geek-terminal
"C:/Users/longyaosi/python-sdk/python3.13.2/python.exe" tools/build_run.py
```

- **platformio 只装在 `C:\Users\longyaosi\python-sdk\python3.13.2\python.exe`**，
  托管 python（3.13.12）里没有，别换解释器。
- 构建目录是 `.wb_build`（`platformio.ini` 里改过 `build_dir`）。
- **别删 `.pio`**：会触发依赖库重下，还会撞 safe-delete 拦截把环境搞崩。要重编只删 `.wb_build`。

### 2.2 烧录

```bash
"C:/Users/longyaosi/python-sdk/python3.13.2/python.exe" tools/flash_run.py COM7
```

`flash_mode` 必须是 **dio**，`flash_run.py` 已经写死，别用裸 esptool 手敲漏掉。

### 2.3 抓日志

```bash
"C:/Users/longyaosi/python-sdk/python3.13.2/python.exe" tools/reset_capture.py COM7 boot.txt
"C:/Users/longyaosi/python-sdk/python3.13.2/python.exe" tools/serial_cmd.py COM7 "help" 20
```

### 2.4 ⚠️ 每次编译后必做：确认真的编进去了

```python
# 对比 .o 与 .cpp 的 mtime，obj 必须 >= src
```
本项目踩过多次"日志返回 0 但 PIO 静默跳过编译"，烧的还是旧固件。
**最可靠的判据是 `.o` 的 mtime，不是退出码，也不是日志行数。**
日志文件名别猜：`build_run.py` → `build_sdkdef.log`，`flash_run.py` → `flash_sdkdef.log`。
详见 [`01` §6](01-板级硬事实与构建烧录.md)。

### 2.5 开机成功标志

```
[Display] init ok
[Touch] init ok
[App] buf pixels=57600 bytes=115200 ptr=0x3d8712dc   ← 0x3d… 是 PSRAM 段
[App] init ok
[BOOT] Geek Terminal ready
```

无害告警（**不是 bug，别去修**）：
- `gpio_set_level(227)` / `Invalid pin selected` —— GT911 操作 INT/RST = -1
- 偶发的 NTP 单次超时（已多服务器兜底）

## 3. 目录结构

```
geek-terminal/
├─ platformio.ini        # 板级配置，注释里写了"血泪教训，勿改"
├─ partitions_16MB.csv   # ⛔ 没被使用！用了就 bootloop（见 02 §1.4）
├─ src/
│  ├─ main.cpp
│  ├─ config/
│  │   ├─ pins.h         # 引脚分配
│  │   └─ lv_conf.h      # ⚠️ 陷阱：这份**不生效**！真正生效的在 vendored 库里，见 14-E8
│  ├─ hal/               # 硬件抽象层：display / touch / battery / ntp_time / serial_console
│  ├─ app/               # 各个屏：launcher clock settings wifi weather memory sysinfo game draw
│  │   ├─ nav.cpp        #   屏导航 + 懒创建 + 回主页回收
│  │   ├─ status_bar.cpp #   顶部状态栏（时间/电池/WiFi/蓝牙图标）
│  │   ├─ icons.cpp      #   手绘线条图标
│  │   ├─ screensaver.cpp#   息屏状态机 ACTIVE→DIM→OFF
│  │   └─ browser_screen.cpp  # ⚠️ 60KB，浏览器主控（UI + 缓存 + 下载 + 内置 HTTP 服务）
│  └─ browser_engine/
│      ├─ include/
│      └─ src/
│          ├─ tactilebrowser_core.cpp  # 对外 API + PSRAM 分配器 tb_alloc
│          ├─ html_parser.cpp          # Lexbor 封装
│          ├─ css_parser.cpp
│          ├─ layout_engine.cpp        # ⚠️ 60KB，平铺排版 + 垃圾过滤（改排版看这）
│          ├─ dom_renderer.cpp         # DOM → 布局树
│          └─ lvgl_renderer.cpp        # 布局树 → LVGL 控件 + 网络请求/UA
├─ docs/                 # 01～14
└─ tools/                # 构建/烧录/探针脚本（388 个，大多是一次性日志，见 §6）
```

> ⚠️ **LVGL 配置有两份，改错那份不生效**（2026-09-23 核实）：
> 编译时真正生效的是 `../4.0inch_ESP32-4848S040/1-Demo/Demo_Arduino/Libraries/Lvgl/lv_conf.h`
> （`LV_MEM_POOL_IN_PSRAM 1`、`LV_MEM_SIZE (128U*1024U)`，26972 B）。
> `src/config/lv_conf.h`（25690 B、`LV_MEM_SIZE (192U*1024U)`、无 `LV_MEM_POOL_IN_PSRAM` 宏）
> **不会被用到**。改 LVGL 行为请先确认改的是前者。详见 [`09` E8](09-坑点速查表.md)。

### 浏览器数据流

```
URL → lvgl_renderer（HTTP GET，按 host 选 UA）
    → html_parser（Lexbor 建 DOM）
    → dom_renderer（DOM → 布局树，节点/文本走 tb_alloc 进 PSRAM）
    → layout_engine（平铺排版 + 垃圾过滤 → 一行行 flat 行）
    → lvgl_renderer（建 LVGL 控件）
    → 页面 HTML 进 PSRAM 缓存（URI→HTML，TTL 5min，3 槽 LRU）
```

**缓存命中时跳过下载**，直接 `tactilebrowser_parse_html_buffer()` 从缓存解析。

## 4. 串口命令全集

串口 115200，直接打字回车。

| 命令 | 作用 |
|---|---|
| `help` / `?` | 帮助 |
| `nav <screen>` | 切屏。`screens: launcher clock settings wifi game browser draw memory sysinfo weather`<br>`nav launcher` 特殊：= 回主页，销毁除 Launcher 外所有 Activity |
| `browser <url>` | 开浏览器并加载 URL |
| `vp <width>` / `vp 0` | 排版视口宽度，`0` = 自动（读页面 `<meta viewport>`） |
| `flat on\|off` | 平铺排版开关，**改完要重新加载页面才生效** |
| `flatdump <n>` | 平铺诊断 dump 的行上限（默认 60，排查"第 60 行之后的内容"用） |
| `dl` | 把当前页 HTML 存进 LittleFS（页面须还在 5 分钟缓存里，否则先刷新） |
| `ls` | 列出已存页面 |
| `serve` / `servestop` | 把已存页面用 HTTP 共享出去，PC 浏览器访问 `http://<板子IP>/` 看 |
| `wifi` | WiFi 状态 |
| `bat` | 探测板载 PMIC（电量计）并 dump 寄存器 |
| `mem` | 内存信息（DRAM + PSRAM，含总量） |
| `reboot` / `version` / `time` | 重启 / 版本 / uptime |

**典型排查流程**：`browser <url>` → 看 `[Flat]` dump（不够就 `flatdump 200` 再刷）→
`dl` + `serve` 把设备收到的**原始 HTML** 拉到 PC 上对比。

## 5. 常用工具脚本

`tools/` 里 388 个文件，绝大多数是一次性日志/探针。**真正常用的就这些**：

| 脚本 | 用途 |
|---|---|
| `build_run.py` | 构建（设好了 safe-delete 阈值，别用裸 pio） |
| `flash_run.py <port>` | 烧录（写死 dio） |
| `reset_capture.py <port> <out>` | 复位并抓启动日志 |
| `serial_cmd.py <port> "<cmd>" <sec>` | 发命令读响应（不复位） |
| `cap_log.py` / `cap_cmd.py` | 抓日志 |
| `verify_flow.py <port> <url>` | 生命周期压测：进入→加载→退出→再进入，全程记内存 |
| `a2l.py <addr>...` | addr2line 批量解析崩溃地址 |
| `probe_bing10.py <port> <out>` | 浏览器渲染探针（自动 `flatdump 200`） |
| `fetch_dev_html.py <port>` | 把设备收到的原始 HTML 拉到 PC |
| `probe_serve.py <port> <out>` | 测 `dl` + `serve` 链路 |
| `gen_fonts.py` / `gen_font.js` / `font_glyphs.py` | 中文字体生成（见 `09`） |
| `minimal_run.py` | 极简工程二分法（bootloop 定位） |
| `verify_docs.py` | **校验 docs/ 的链接、代号、残留旧名**（改完文档跑一遍，防止链接腐烂） |

其余 `inspect_*.py` / `fix_*.py` / `probe_*.txt` 都是**当时的取证脚本，一次性**。
（`fix_*.py` 是一次性源码补丁脚本，已经跑完并写进源码了，不要重复执行。）

## 8. 工作约定

跨项目通用的协作方式见仓库根的 **`AGENT.md`**。与本项目强相关的几条：

1. **先挖根因再修** —— 看到现象先取证（抓原始 HTML、addr2line、对比 mtime），别急着改。
2. **改完必须上板验证** —— 本项目"编译通过"≠"生效"，见 §2.4。
3. **破坏性操作先列清单等确认** —— 删大文件、改产品语义、动 `platformio.ini` 板级配置。
4. **知识落盘** —— 排查出的新坑，补进 `14`；涉及某个专题的，同时补进对应编号文档。
